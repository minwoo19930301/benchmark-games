# 새 패러디 5종 검증 기록

이 문서는 2026-09-19 로컬 소스의 검증 범위를 기록합니다. 시뮬레이션 완주, 브라우저에서 실제 화면을 확인한 범위, 성능 측정과 공개 배포는 별도의 증거로 구분합니다. 최종 전체 검사와 실제 브라우저 실행 결과를 아래에 기록합니다.

## 실행 구조와 완료 조건

게임 목록은 기본 경로 및 `#arcade`에서 열립니다. 기존 `#mario`, `#sonic`과 새 게임 5종을 합쳐 총 7개이며, 목록의 연속 벤치마크 대상은 새 게임 5종입니다.

| 경로        | 완료 조건                                            | 표현 방식                     |
| ----------- | ---------------------------------------------------- | ----------------------------- |
| `#smash`    | 상대의 스톡 3개를 실제 장외 판정으로 소진            | Three.js 옥상 발판 난투       |
| `#ocarina`  | 선율석 3개 활성화, 수호자 격파, 제단에서 상호작용    | Three.js 숲 신전 탐험         |
| `#commando` | 동료 3명 구출, 고철 탱크 격파, 오른쪽 탈출 지점 도달 | Canvas 2D 횡스크롤 픽셀 액션  |
| `#iron`     | 상대보다 먼저 2라운드 승리                           | Three.js 입체 격투            |
| `#pocket`   | 서로 다른 야생 친구 2종 포획 후 라이벌 미소 격파     | Canvas 2D 타일 탐험·턴제 전투 |

공통 실행기는 120Hz 고정 간격으로 각 게임의 `step()`을 호출합니다. `benchmark()`는 이동·공격·방어·상호작용 등의 일반 입력을 반환합니다. 완주 컨트롤러는 플레이어 위치나 HP를 직접 바꾸거나 퀘스트 완료 상태를 강제로 설정하지 않습니다. 개별 충돌·전투 단위 테스트에서만 특정 조건을 만드는 상태 설정을 사용합니다.

## 결정적 시뮬레이션 완주

2026-09-19 Node에서 각 게임의 실제 시뮬레이션과 벤치마크 함수를 불러와, 30·60·120Hz 화면 갱신 일정마다 내부를 120Hz로 나누어 실행했습니다. 세 일정 모두 아래 동일한 승리 결과를 냈습니다. 시간은 게임 내 경과 시간이며 실제 브라우저 FPS 측정값이 아닙니다.

| 게임            | 세 일정의 결과 | 시뮬레이션 시간 | 최종 상태                                     |
| --------------- | -------------- | --------------: | --------------------------------------------- |
| 옥상 대난투     | 모두 `won`     |        61.658초 | 내 스톡 3, 상대 스톡 0, 11,800점              |
| 야근의 오카리나 | 모두 `won`     |        17.583초 | 선율 3/3, 수호자 격파, 2,880점                |
| 깡통 특공대     | 모두 `won`     |        30.467초 | 동료 3/3, 장갑 10, 13,990점                   |
| 철권 택배       | 모두 `won`     |        31.667초 | 라운드 2:0, 내 체력 90, 8,780점               |
| 첫 번째 모험    | 모두 `won`     |        12.667초 | 친구 2종 포획, 라이벌 HP 0, 구슬 4개, 1,600점 |

Pocket의 별도 테스트는 고정 간격 실행기 없이 `step(1 / Hz)`에 30·60·120Hz를 직접 넣어도 각각 13.233·12.750·12.667초에 승리함을 확인합니다. 이 추가 검사는 큰 간격에서도 게임이 완료되는지를 검사하며, 공통 실행기의 고정 120Hz 결과와 같은 실험은 아닙니다.

### 기능 테스트 범위

- **옥상 대난투:** 물리 이동과 더블 점프·복귀, 실제 접촉 시 피해와 밀쳐내기, 방패 소모, 장외와 스톡, 완료 이후 정지.
- **야근의 오카리나:** 공격 거리·방향·한 번의 휘두르기당 피해, 전방 방패와 후방 피격, 구르기·점프 입력, 선율의 순서·근접 조건, 닫힌 문·연못 충돌, 보스와 제단의 완료 조건.
- **깡통 특공대:** 점프와 착지, 피격 후 보호 시간, 가까운 동료 구출의 단일 처리, 실제 투사체로 적 격파, 수류탄 수량과 전체 임무 완료.
- **철권 택배:** 펀치 연속 타격, 발차기 거리, 깊이 방향 회피, 공격 예고와 가드·스태미나, 라운드 전환과 2라운드 선승.
- **첫 번째 모험:** 이동 충돌과 이동량에 따른 조우, 속성 삼각관계, 공격 대기 시간, HP 45% 포획 기준, 중복 포획 구분, 구슬·회복 떡 수량, 진료소 보충, 친구 교체·쓰러짐, 라이벌 조건, 승패 이후 정지. 픽셀 뷰의 상태 비변경·DPR 제한·해제 이후 정지도 검사합니다.

공통 실행기 16개 테스트는 준비/완료/일시정지 시 RAF 정지, 입력 해제, 백그라운드 시작, 오류 후 재개 차단, 재시작·해제와 결과 중복 방지를 검사합니다. 통계 3개 테스트는 지연 프레임을 포함한 FPS·p95 계산과 잘못된 로컬 기록·저장 실패를 검사합니다.

게임별 파일은 `tests/retro-fighters.test.mjs`, `tests/retro-ocarina.test.mjs`, `tests/retro-commando.test.mjs`, `tests/retro-pocket.test.mjs`입니다. 기존 Mario·Sonic 테스트를 대체하지 않습니다.

Chrome 배포용 빌드에서 기본 1404×689 화면으로 검사했습니다. 실제 게임 캔버스는 1404×482였으며, 아래 성능값은 이 한 환경의 관측입니다.

## 성능 기록의 의미

새 게임의 자동 실행이 `won` 또는 `lost`로 끝나면 평균 FPS, 프레임 간격 p95, 평균 CPU 작업 시간, 완료 상태, 점수, 게임 내 시간, 화면 크기·픽셀 비율·브라우저 정보를 기록합니다. 수동 실행은 이 자동 벤치마크 기록에 추가하지 않습니다.

- 평균 FPS는 유효한 프레임 간격들의 합을 기준으로 계산합니다. p95는 그 간격들의 95백분위수입니다.
- CPU 작업 시간은 시뮬레이션 갱신 및 렌더링 명령 실행 구간을 측정합니다. GPU 완료 시간이나 브라우저 전체 비용을 측정하지 않습니다.
- 시뮬레이션은 120Hz이며 화면 렌더링 빈도와 다릅니다. 브라우저를 숨기거나 창 포커스를 잃으면 일시정지하고, 다시 시작할 때 오래된 프레임 간격을 누적하지 않습니다.
- WebGL draw calls와 Canvas 2D의 그리기·합성 작업은 서로 다른 작업 단위입니다. 원시 호출 수만으로 게임 간 GPU 성능을 비교하지 않습니다.
- 최근 30개 결과를 현재 브라우저의 `localStorage`에 보관합니다. JSON 내보내기는 로컬 다운로드이며 서버 전송 기능은 없습니다. 저장소를 쓸 수 없으면 영구 보관이 되지 않을 수 있습니다.

같은 브라우저·기기·화면 크기·픽셀 비율에서 실행한 결과를 비교해야 합니다. 이 프로젝트의 수치는 범용 하드웨어 순위나 모든 기기에서의 프레임 보장이 아닙니다.

JSON의 `game` 값으로 렌더러를 구분할 수 있습니다. `smash`, `ocarina`, `iron`은 WebGL이고 `commando`, `pocket`은 Canvas 2D입니다. 원시 `drawCalls` 필드는 렌더러별 의미가 다르며, 공통 성능 비교에는 FPS·프레임 간격·CPU 작업 시간을 사용합니다.
